## 1. 三个真问题（按影响大小排序）

### 1.1 词的量级太小 —— 排第 1 也没几个人（最大问题）

832 次展示 ÷ 28 天 ≈ **每天 30 次曝光，全站**。

反过来推：`getting-paid-without-stripe` 28 天 332 次展示，说明它的目标词月搜索量大概在**几百量级**。这种词就算你排到第 1 位，一个月也最多 30–50 次点击。

> 你现在陷入了「极长尾陷阱」：竞争确实低，但池子太小。为了躲开大站，把词一路退到没人搜的地方，等于赢了一场没有奖品的比赛。

**必须往上走一层**：从「月搜 200–500、KD 极低」→「月搜 1000–3000、前 5 有 DR 20–40 的站」。后者才是既有量又能赢的区间。

### 1.2 CTR 1.2% —— 排在第 9 位，正常该有 6–8%

这是**最容易修、见效最快**的一项，而且不需要写任何新内容。

同一条数学：

| 情形 | 展示 | CTR | 点击 |
|---|---|---|---|
| 现在（排名 8.9） | 332 | 1.2% | **4** |
| 标题摘要修好（排名不变） | 332 | 6% | **20** |
| 内容加深 + 内链推到 4–5 位 | 600+ | 8% | **48** |

**不动排名，只改标题，这一篇就能从 4 个点击变成 20 个 —— 相当于你现在的全部流量翻 5 倍。**

为什么 CTR 只有 1.2%？两个原因：
1. **标题不像"人会点"的东西**。`Getting Paid Without Stripe: My Ko-fi + PayPal Setup` —— 这是"记录我做了什么"，不是"解决你的问题"。搜这个词的人想知道"我该怎么办"，标题要冲着他喊。
2. **展示分散在大量长尾词上**。平均排名 8.9 是被少数几个好位次拉高的，大部分展示可能来自排 30+ 的词（那些词几乎不会被点）。所以真实情况是：**你在少数词上排第 8，在多数词上排第 30**。

### 1.3 大部分页面 0 排名 + 全站 0 外链

deploy 簇 16 篇没进点击榜，原因在 §3。

## 2. 双轨策略：先摘低垂果实，再换战场

两条轨并行，但**优先级完全不同**：

### Track A（本周开始，2–4 周见效）—— 把已经排上来的页面推到前 5

这是全站 ROI 最高的动作，因为你已经有排名基础，不用等 Google 重新建立信任。

**具体做法（按这 8 篇逐个过）：**

1. **导出 GSC 里有点击的全部页面**（估计 8 篇左右），按展示排序。
2. 对每篇做三件事：
   - **改标题**：从"我做了什么"改成"你该怎么办 + 具体结果"。
     - ❌ `Getting Paid Without Stripe: My Ko-fi + PayPal Setup`
     - ✅ `No Stripe? Get Paid in 48 Hours With Ko-fi + PayPal`
   - **改 description**：必须包含一个具体数字或结果（费率、到账时间、门槛）。这是 SERP 里唯一能制造"点我"冲动的元素。
   - **内容加深 30%**：补上真正只有你能写的东西 —— 实际费率和到账天数截图、被拒的经过、审核等了几天。然后更新 `dateModified`。
3. **给这 8 篇加 3–4 条站内入链**（从相关老文链过来），把权重集中过去。

> 判断标准：4 周后这 8 篇的平均排名有没有从 9–20 进到 5 以内。进了，说明这条路成立，可以继续复制。

### Track B（本周开始，60–90 天见效）—— 换战场到 payments / Lemon Squeezy

**deploy 簇封盘，不再新增。** 理由是数据已经给了答案：payments 在排名，deploy 不在。继续往 deploy 投入等于每次从零开始建立信任；而往 payments 投入，Google 已有的相关性判断会直接传递过去。

## 3. 为什么 deploy 那 16 篇打不动 —— 判据需要改

`content-strategy-no-comparison.md` §2 的核心判据是：

> ≥2 条 UGC（Reddit / Stack Overflow / GitHub Discussions）→ **可打**

这条判据的推理链断了。**UGC 出现在前 5，说明的是"意图已经在 SERP 内被满足"，不是机会，是警告。**

- 用户搜 `vercel build failed` 的真实需求是「30 秒内给我一个能试的修复」。那条 SO 帖子已经把 npm / Node 版本 / 缓存 / peer-deps / monorepo / 环境变量全部原因列完了 —— Google 判定意图已满足，没有任何理由推第 12 个答案上去。
- 更致命：**点击不需要**。用户在摘要里扫一眼就有答案，压根不点。

> 你 9 月 4 日那次实测（`404 on refresh vercel`）其实已经看到真相：排上来的是 **jsschools.com 这类小站**。真正说明"可打"的信号是「**有低 DR 站排进前 5**」，当时把功劳记在了 UGC 头上。

### 修正后的判据（替换原 §2 表格）

| 判据 | 加分（可打） | 减分（放弃） |
|---|---|---|
| 前 5 是否已有 **DR < 40** 的站 | ✅ +3 —— 最强的可赢信号 | ❌ −3 全是 DR 60+ |
| 是否存在**单一答案页通吃**全部原因 | ✅ 答案分散在多个来源 | ❌ 一条 SO 帖/一页官方文档全覆盖 |
| 查询是否需要**多步骤执行** | ✅ +2 | ❌ −2 一句话答完 |
| 是否有**商业/实施意图** | ✅ +2 读者正在花钱或配置 | ❌ −2 纯排错、修完就走 |
| **词量级是否 ≥ 1000/月** | ✅ +2 | ❌ −2 月搜几百，排第 1 也没量 |

**≥5 分才写，≤2 分换词。** 用这个标准回测，deploy 簇的报错文大多在 0 分上下 —— 它们从出生就不该被写。

## 4. 拿链接 —— 你从来没做过的那件事

11 周 0 外链建设 = 排名天花板极低。目标：60 天做到 15–20 个引荐域名。

按性价比排：

1. **dev.to 同步 3 篇**（最高性价比）。选 LS webhook / checkout / license 三篇，改写成 dev.to 风格，**canonical 指回 shiptocash.com**。dev.to DA 90，带爬虫 + 带品牌搜索 + 带真实点击。今天就能做。
2. **Reddit 真实回答 5 条**。r/webdev、r/SideProject、r/SaaS 搜 `lemon squeezy`，回答里把**完整解法写出来**，最后附「详细版在这里」。硬贴链接会被删号。
3. **GitHub 侧链**：给 `awesome-astro` / `awesome-vercel` 提 PR；把自己的 guides 挂到个人 repo README（GitHub 是 DR 100 dofollow 域）。
4. **做 1 个免费计算器**：Lemon Squeezy / Paddle / Stripe 手续费对比计算器（纯工具，不是评测文，不违反禁对比文规则）。工具页是最容易自然吸链接的资产。
5. **同层级互引**：找 5 个 DR 10–30 的同类小站，读完写一篇更深的，邮件告知 + 请求互引。

> ⚠️ 不买链接、不进链接农场、不做 PBN。新站被识别一次就废。

## 8. 顺手要修的两个小事

1. **GA4 没配**（`src/config/site.ts` 里 `ga4Id` 为空）。你现在只能看到 Google 给了多少曝光，看不到进来的人停了几秒、去了哪页。装 GA4 或用 Cloudflare Web Analytics（免费、无 cookie）。
2. **`dateModified` = `datePublished`**（30 篇全部）。挑真正加深过内容的 5 篇更新 `dateModified` 是正确信号；只改日期不改内容是作弊，别做。
